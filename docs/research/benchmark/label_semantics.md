# 标注口径差实测 (审计 F7) — 2026-11-23

数据: `output/sdg_shelf` (200 图 = train 160 + val 40, 场景级留出)

| 检验 | 结果 |
|---|---|
| 逐图一致性 (标签行数 vs 标注记录数) | 全部一致 |
| 可见度过滤 (可见面积 <15% 不入库) 丢弃 | **0 / 5240 = 0.0** |
| 单类化丢弃 class 1 (OOS gap) | 824 / 5240 = 0.157252 |
| 合成有效框/图 (train, 单类后) | 21.82 |
| 真实 SKU-110K train 框/图 | 147.04 (8219 图 / 1208482 框) |
| 框密度比 (真实/合成) | **6.74×** |
| R2 训练集里的合成占比 (口径差影响的上界) | **0.019095** (160 合成 / 8219 真实) |
| 保留框里带非合规语义 (朝向错位 class2 + 竞品入侵 class3) | 815 / 4416 = 0.1846 |
| 框来源 | 全部 `object_index_mask` (可见区域紧致框): {'object_index_mask': 5240} |

## 读法

1. **审计 F7 记的"合成丢弃遮挡物"在这套数据上从未发生** —— 可见度过滤一次都没触发 (0/5240), 且逐图标签行数与标注记录数完全一致。F7 是代码层面的观察, 不是数据层面的事实。
2. 真正存在的口径差是三条: (a) 单类化时丢 OOS gap 框 (0.157252); (b) 合成框是**可见区域**紧致框, 真实框是整品框; (c) 框密度差 6.7× (21.8 vs 147.0 框/图)。
3. 对头条结论 (R2 vs R0) 的影响上界 = 合成在 R2 训练集里的占比 = **0.019095**; 口径差最多只能污染这部分信号, 而实测 Δ(R2−R0) = +0.07pp —— 量级上不可能解释"未检出差异"。
4. 对 R1 (纯合成臂) 影响则是 100%: R1 的数字就是"当前标签语义下的纯合成"水平。
5. **框密度比 6.74× 是偏向真实的上界估计**: 合成框是**可见区域**紧致框, 换成整品框只会更大 (可见面积占比 <1) → 合成侧的框密度只会更低 → "合成的标注效率只有真实的 1/6.7"这个说法**保守**, 不是夸大。

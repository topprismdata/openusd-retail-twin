# 四臂实证（P0-1）方法学有效性审计

- 审计日期：2026-11-18 ｜ 范围：`pipelines/shelf_sdg/` + `docs/research/benchmark/` + `docs/SYNTHETIC_VS_MANUAL_ANNOTATION.md` + `docs/JUDGE_VALIDATION_P0C.md`
- 方法：只读代码与产物复算；一切数字标注 `文件:行`；仓内不可核验者明确标注，不臆断真伪。
- 边界：`output/`、`runs/`、SKU-110K 数据集、训练权重均不在仓内。

## 0. 结论

**仓内证据支持**：在 SKU-110K 密集真实货架域上，**向全真实训练集追加少量合成数据未检出显著差异**（ΔmAP@0.5 = −1.77pp，擦边通过自定的 ≤2pp 规则）。

**⚠️ 2026-11-23 复跑后的修正（本条结论的写法要改，结论方向不变）**：四臂补了多 seed 复跑（R0/R1/R2 各 seed 43/44/45/**46**，R1/R3pm 到 47；`35`/`40` 号链），发现已发布的那一对**不是协议可比的 seed 复跑**——2026-11-08 那一版是 macOS/MPS 跑的（`protocol.device = mps`，无数据指纹），且 R1/R2 的**合成数据此后换过**（旧划分 → 场景级留出）。当前协议下同 seed 配对复跑给出 **Δ(R2−R0) = +0.11 / +0.04 / +0.25 pp，mean +0.13pp，95% CI [−0.13, +0.40]** → **未检出差异，而且 95% 置信下最多劣化 0.40pp**（比"≤2pp 擦边通过"更强也更诚实：那个 2pp 阈值的余量 0.23pp 本就小于臂间 seed 波动）。R1 纯合成当前协议 **0.2437 / 0.2532 / 0.2294**（mean 0.2421 ± 0.0120；历史协议 0.1330 是旧合成划分的值）→ 比 R0 低 64.1pp，CI [−66.98, −61.25] → 负结论不变。证据：`docs/research/benchmark/fourarm_seed_variance.md`。

**仓内证据不支持**：README 宣称的「合成可替代大规模手工标注」——**没有任何一个臂减少过真实标注量**，该命题从未被测量。（2026-11-22 起由标注预算臂单独测量，结论为**负**。）

**仓内证据反驳**：「前提 = 域对齐」——把"域对齐"做成**只差一个变量**的臂后（2026-11-23 协议对齐复跑），域对齐配方**不但没帮上忙，还显著变差**：Δ(R3pm−R1) = **−11.45pp**，95% CI [−21.78, −1.13]；三因子里它只动了密度与尺度，**朝向因子根本没碰**（misalign 是绕竖轴转，不是形状变化），且副作用把 42% 的训练框变成倾斜商品。旧的 R3-full 数字（0.182）不可复现已作废。

**⚠️ 2026-11-23 晚订正**：上一版这里写的是"生成器无法正确表达域对齐"——**这个诊断是错的**。商品箱子的长宽本来就是生成器参数（PACK_W/PACK_H），朝向因子**能**表达，只是**从没被操作过**；真实域逐图中位宽高比均值 1.05 vs 合成 0.32。已加形状先验（脚本 41–43）并由单独的臂回答"真的把朝向因子对齐过去有没有用"。

**此外**：评测集 n、合成集规模、计数指标、域差距实测值、盲评 rubric、3.6 图/min 计时原先全部缺失或未落盘；其中 **Δ=1.77pp 的统计显著性原为"仓内不可判定"，现已可判定**（见上）。

同 seed 配对 (只用协议可比的运行, n=5: 补 seed 46/47): **Δ(R2−R0) = +0.11 / +0.04 / +0.25 / +0.23 / +0.17 pp → mean +0.13pp,
95% CI [+0.05, +0.26]** → **CI 整段在 0 以上 = 差值显著为正** (95% 置信下至少高 0.05pp), 5 个 seed 差值全为正、方向一致 → 追加合成未损害基线 (严格说还略优, 但幅度仅 +0.16pp);
**Δ(R1−R0) = −63.81 / −63.14 / −65.39 pp → mean −64.11pp, CI [−66.98, −61.25]** → 显著劣化。

两点必须一起说:
1. **已发布那一对不能当 seed 复跑** —— 2026-11-08 那版是 macOS/MPS (无数据指纹), 且 R1/R2 的
   合成数据此后换过 (旧划分 → 场景级留出)。证据: 纯合成臂 R1 旧协议 0.1330, 换划分后
   0.2265 (2026-11-21 场景级留出复跑) / 0.2437 / 0.2532 / 0.2294 (本轮)。
   → "Δ = −1.77pp"只能当**历史协议的观测值**, 不是当前协议的效应量。
2. **0.23pp 余量本身就不成立** —— R2 臂换 seed 的波动 (0.8678 → 0.8828 → 0.8850 → 0.8857, 极差 1.79pp)
   大于它与 2pp 阈值的余量; "擦边通过 ≤2pp 规则"这句话当年就缺方差支撑, 现在有了方差反而更清楚:
   那个差值是**协议差异 + 单次运行运气**的混合, 不是"追加合成造成的轻微损害"。
   **n=3→5 后 CI 从跨 0 变成整段在 0 以上** (从"未检出差异"变成"显著为正, 但幅度仅 +0.16pp") —— 精度提升来自多 seed, 不是来自"重跑一次"。

### 为什么「混合范式成立」是无效推论

1. R2 = 全量真实 train + 合成追加，**从未减少真实标注量**；要回答「替代」需要 real-k 子集 + synth-N 的对照臂，仓内不存在。
2. 合成占比 ≤5% 时「R2 ≈ R0」是构造性必然，与合成能否替代无关。
3. R1 = 0.133 恰恰否证替代性：唯一不依赖真实标注的臂崩到 0.133。
4. 判读实现比预注册文档少一个条件：`18:46-53` 的 R2 结论块只检查 `abs(delta) <= 2.0`，不检查 `R1 < R0`，因此会无条件输出「混合范式成立」。
5. R3 一次改 4 个因子（`16:30`）→ 「R1 失败根因 = 密度/面积/朝向」的归因**不可识别**。

## 3. 统计效力

- 每臂评测图数 n **未记录**（`SKU-110K.yaml` 不在仓）；仓内唯一 n 是计数子集 600（`17_count_eval.py:20`）。
- 以 n≈2339（仓外参照）估算：SE(mAP@0.5) ≈ 0.0066（±1.29pp），两臂独立处理 SE_diff ≈ 0.0093（±1.82pp）→ |Δ|=1.77pp **小于该阈值**；配对处理需 per-image 结果，仓内缺失 → **仓内不可完成判定**。
- 等效量级：1.77pp × 2339 ≈ 41 张图的 AP 变化，与「少数图翻转」不可区分。
- `mem_guard()` 可静默把 batch 4 降到 2（`14:71-79`），`--resume` 硬编码 batch=2 且不落记录（`14:158-168`）→ 协议哈希检不出实际配置。
- 「3.6 图/min」：**仓内无任何计时/吞吐代码**（`02` 无 `perf_counter`；全仓 `图/min|per_min|throughput` 零命中）→ **不可核验**。「1 万图可扩展」为外推。
- 计数评测取「按文件名排序的前 600 张」而非随机抽样（`17_count_eval.py:42`）→ 系统性偏置。

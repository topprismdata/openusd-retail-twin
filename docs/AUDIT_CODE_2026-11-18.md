工程债的**主形态不是"代码写得烂"，而是"研究脚本与产品线混在一个仓里"**：
82 个脚本里只有 **8 个**被编排器 `run_pipeline.py` 接线，其余 74 个是按需手动跑的一次性研究脚本，

## 3. 已修复的实质缺陷（本次补丁）

| # | 缺陷 | 位置 | 影响 | 修复 | 验证 |
|---|---|---|---|---|---|
| B1 | 用进程加盐的 `hash()` 播种随机数 | `36_open_asset_zoo.py:181` | Python 3 的 `hash(str)` 每次进程都不同 → TOPPRISM 标签条码**每跑一次图案都变**，与仓内"确定性噪声晶格（跨进程逐位一致）"的纪律直接冲突 | 改用 `zlib.crc32(key.encode())` | 3 个独立进程输出：`crc32 → {'8 6'}` 恒定；`hash() → {'8 9','5 9','8 4'}` 每次不同 |
| B2 | 四臂产物不记录数据组成与实际训练配置 | `14_sku110k_baseline.py:202-215` | R2 的"混合比"不可知；`mem_guard()` 静默降 batch、`--resume` 硬编码 batch=2 都不落记录 → `protocol_hash` 检不出实际配置 | 新增 `dataset_composition()`（记录各来源图数与 `synth_ratio`）与 `actual_train_config` | 字段写入 json；`18_four_arm_report.py` 的表格与结论直接读取 `synth_ratio` |
| B3 | 报告判读缺预注册条件，且措辞超出证据 | `18_four_arm_report.py:46-53` | 原实现只判 `abs(Δ)≤2pp` 就会输出"混合范式成立：合成可替代大规模手工标注"——该命题在本仓**没有任何减少真实标注量的臂**支撑 | 补上 `R1<R0` 条件；措辞降级为"未检出差异"；新增"结论边界"小节 | 用假 json 驱动生成器实测：R0/R1/R2 场景输出新措辞并打印合成占比。**⚠️ 2026-11-23 复跑后的补充**: 那个 ≤2pp 阈值本身余量只有 0.23pp, 而 R2 臂换 seed 的波动达 1.72pp (0.8678/0.8828/0.8850) → 阈值判据的余量小于噪声; 现改为按 seed 配对给 CI (当前协议 n=3: Δ(R2−R0) = +0.11/+0.04/+0.25pp, mean +0.13, CI [−0.13, +0.40]) → "未检出差异 + 能排除 >0.40pp 劣化" |
